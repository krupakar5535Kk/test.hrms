### FINDING DOMAIN A: PAYROLL ENGINE CORRECTNESS & SNAPSHOT INTEGRITY

#### Finding A.1 — Conflicting 480-Minute Full-Day Assumptions vs. Approved 420-Minute Net Day
- **Finding ID:** `DEF-A1`
- **Original A3.13.2 Location:** Section 2.2, lines 310, 317.
- **Exact Defect:** The calculation engine in A3.13.2 calculated absent minutes as `COUNT(*) FILTER (WHERE ad.day_status = 'ABSENT') * 480` and unpaid leave minutes as `SUM(la.total_days * 480)`, directly contradicting the approved 420-minute standard day.
- **Root Cause:** Conflating the 8.0-hour gross shift window (10:00 to 18:00 = 480 elapsed minutes) with the net scheduled payable working day.
- **Proposed Correction:** PRD v1.8 §11 line 297 explicitly defines:
  $$H_{\text{std}} = N_{\text{sched}} \times 7.0\text{ hours} \quad \implies \quad M_{\text{std}} = H_{\text{std}} \times 60 = N_{\text{sched}} \times 420\text{ minutes}$$
  Under DEC-01, an employee present for the full 10:00–18:00 shift has 60 minutes deducted for lunch, yielding exactly 420 net payable minutes. Therefore, full-day absence and leave deductions must be computed using 420 minutes per scheduled day.
- **Exact Corrected SQL:**
  ```sql
  -- Correct 420-minute standard net scheduled day multiplication
  v_absent_mins := COALESCE(COUNT(*) FILTER (WHERE ad.day_status = 'ABSENT') * 420, 0);
  v_unpaid_leave_mins := COALESCE(SUM(la.total_days * 420), 0)::int;
  ```
- **Related Approved Decision:** PRD v1.8 §11, DEC-01, Test Case `TC-CALC-01` (`docs/08_ROADMAP_AND_TESTING_STRATEGY.md:80`).
- **Verification Method:** Static code inspection against PRD v1.8 §11.
- **Verification Status:** **STATICALLY VERIFIED**.
- **Remaining Risk:** Custom shift templates (e.g. half-days or 6-day workweeks) require formal schema extensions in Phase 3.

#### Finding A.2 — Enforcement of Approved Zero-Payable Policy for Leaves and Holidays
- **Finding ID:** `DEF-A2`
- **Original A3.13.2 Location:** Section 2.1 lines 88–90; Section 2.2 lines 317–324.
- **Exact Defect:** A3.13.2 included logic to calculate `paid_leave_days` when `lt.is_paid = TRUE` and attempted to credit paid leave into payable minutes.
- **Root Cause:** Implementing generic HRMS leave accrual assumptions instead of adhering to the approved project baseline.
- **Proposed Correction:** PRD v1.8 §9 line 280 states:
  > *"CL, SL, PL, and LWP: 0 payable hours, 0 salary. Recorded as Absent/unpaid for attendance and payroll purposes."*

  > *"Sunday receives 0 payable hours under current policy. Admin-declared public holidays receive 0 payable hours under current policy. Excluded from monthly standard scheduled hours. Configurable policy flags (`is_paid: false`) maintained pending qualified legal counsel review."*

  ```sql
  v_unpaid_leave_mins := COALESCE(SUM(clipped_days * 420), 0)::int;
  -- Paid leave contribution is explicitly 0 paise
  v_paid_leave_earned_paise := 0;
  ```
- **Related Approved Decision:** PRD v1.8 §9, §10, `LEG-01`.
- **Verification Method:** Static code inspection against PRD v1.8 baseline.
- **Verification Status:** **STATICALLY VERIFIED**.

#### Finding A.3 — Boundary Clipping for Multi-Day Leave Applications
- **Finding ID:** `DEF-A3`
- **Original A3.13.2 Location:** Section 2.1 line 94; Section 2.2 line 324.
- **Exact Defect:** Leave filtering used `daterange(v_period.start_date, v_period.end_date, '[]') && daterange(la.start_date, la.end_date, '[]')` but aggregated `la.total_days` in full, erroneously charging entire multi-week leaves to a single period if they crossed month boundaries.
- **Root Cause:** Testing range intersection (`&&`) without clipping the start and end dates to the active payroll period boundaries.
- **Proposed Correction:** Multi-day leaves spanning across payroll periods must have their days clipped strictly to the interval:
  $$[\max(\text{la.start\_date}, \text{period.start\_date}), \;\min(\text{la.end\_date}, \text{period.end\_date})]$$
- **Exact Corrected SQL:**
  ```sql
  WITH clipped_leaves AS (
    SELECT
      la.employee_id,
      (LEAST(la.end_date, v_period.end_date) - GREATEST(la.start_date, v_period.start_date) + 1) AS period_leave_days
    FROM public.leave_applications la
    WHERE la.status = 'APPROVED'
      AND la.start_date <= v_period.end_date
      AND la.end_date >= v_period.start_date
  )
  SELECT COALESCE(SUM(period_leave_days * 420), 0)::int
  INTO v_unpaid_leave_mins
  FROM clipped_leaves
  WHERE employee_id = v_emp.employee_id;
  ```
- **Related Approved Decision:** PRD v1.8 §11.
- **Verification Method:** Boundary-value mathematical verification.
- **Verification Status:** **STATICALLY VERIFIED**.
- **Remaining Risk:** Partial-day (half-day) leaves spanning boundary dates require decimal day support in Phase 3.

#### Finding A.4 — Enforcement of DEC-02 Zero-Payable Incomplete Attendance Sessions
- **Finding ID:** `DEF-A4`
- **Original A3.13.2 Location:** Section 2.2 lines 307–314.
- **Exact Defect:** The engine summed `ad.net_payable_minutes` without verifying that attendance days complied with DEC-02 (incomplete punch sessions with missing check-in or check-out).
- **Root Cause:** Relying entirely on pre-aggregated fields without asserting data invariants.
- **Proposed Correction:** Under DEC-02 Option A (Refined):
  > *"Maximum one Check-In and Check-Out pair per employee per working day ($\le 1$)... Incomplete sessions (check-in without check-out or check-out without check-in) receive exactly zero payable minutes."*
  The engine must assert:
  $$\text{net\_payable\_minutes} = \begin{cases} 
  0 & \text{if } \text{first\_check\_in\_at IS NULL} \lor \text{last\_check\_out\_at IS NULL} \\
  0 & \text{if } \text{last\_check\_out\_at} \le \text{first\_check\_in\_at} \\
  \text{net\_payable\_minutes} & \text{otherwise}
  \end{cases}$$
- **Exact Corrected SQL:**
  ```sql
  SELECT
    COALESCE(SUM(
      CASE 
        WHEN ad.first_check_in_at IS NULL OR ad.last_check_out_at IS NULL THEN 0
        WHEN ad.last_check_out_at <= ad.first_check_in_at THEN 0
        ELSE ad.net_payable_minutes 
      END
    ), 0),
    COALESCE(COUNT(*) FILTER (
      WHERE ad.day_status = 'ABSENT' 
         OR (ad.first_check_in_at IS NOT NULL AND ad.last_check_out_at IS NULL)
         OR (ad.first_check_in_at IS NULL AND ad.last_check_out_at IS NOT NULL)
    ) * 420, 0)
  INTO v_approved_payable_mins, v_absent_mins
  FROM public.attendance_days ad
  WHERE ad.employee_id = v_emp.employee_id
    AND ad.attendance_date BETWEEN v_period.start_date AND v_period.end_date;
  ```
- **Related Approved Decision:** DEC-02 (Approved Baseline).
- **Verification Method:** Static logical analysis against DEC-02 specification.
- **Verification Status:** **STATICALLY VERIFIED**.
- **Remaining Risk:** Offline edge sync creating delayed punches requires admin review before payroll freeze.

#### Finding A.5 — Reconciliation of Gross Elapsed, Lunch Deduction, and Post-18:00 Work
- **Finding ID:** `DEF-A5`
- **Original A3.13.2 Location:** Section 2.1 lines 74–77; Section 5.1 lines 723–730.
- **Exact Defect:** Ambiguity regarding whether post-18:00 work could be double-counted or whether lunch deductions could conflict with evening overtime.
- **Root Cause:** Lack of an explicit, non-overlapping timeline decomposition.
- **Proposed Correction:** Establish the exact timeline decomposition:
  1. Standard working shift window: 10:00 to 18:00 (480 gross minutes).
  2. Statutory lunch window: 13:00 to 14:00 (60 minutes).
  3. Lunch deduction: Exact intersection of employee session $[T_{\text{in}}, T_{\text{out}}]$ with $[13:00, 14:00]$:
     $$M_{\text{lunch}} = \max\left(0, \min(T_{\text{out}}, 14:00) - \max(T_{\text{in}}, 13:00)\right)$$
  4. Standard payable minutes (pre-18:00):
     $$M_{\text{std\_worked}} = \max\left(0, \min(T_{\text{out}}, 18:00) - \max(T_{\text{in}}, 10:00)\right) - M_{\text{lunch}}$$
  5. Post-18:00 elapsed work:
     $$M_{\text{post18\_elapsed}} = \max\left(0, T_{\text{out}} - \max(T_{\text{in}}, 18:00)\right)$$
  6. Post-18:00 approved work: Excluded by default ($M_{\text{post18\_approved}} = 0$). Only included if an Admin explicitly reviews and approves $0 \le M_{\text{post18\_approved}} \le M_{\text{post18\_elapsed}}$.
  7. Net payable minutes:
     $$M_{\text{net}} = M_{\text{std\_worked}} + M_{\text{post18\_approved}}$$
  Because lunch is strictly contained within $[13:00, 14:00]$ and post-18:00 work is strictly contained within $[18:00, \infty)$, the intersection of lunch deduction and post-18:00 work is identically empty ($\emptyset$). Zero double-counting is mathematically guaranteed.
- **Related Approved Decision:** DEC-01, DEC-02, PRD v1.8 §7, §11.
- **Verification Method:** Mathematical set-theoretic proof.
- **Verification Status:** **STATICALLY VERIFIED**.
- **Remaining Risk:** Cross-midnight night shifts are out of scope for Phase 1 (shifts conclude on same calendar day).

#### Finding A.7 — Calculation-Relevant Source Change Invalidation Proof
- **Finding ID:** `DEF-A7`
- **Original A3.13.2 Location:** Section 2.1 lines 71–158; Section 2.3 lines 397–405.
- **Exact Defect:** Lack of a formal demonstration that every calculation-relevant mutation invalidates the cryptographic payroll snapshot.
- **Root Cause:** Audit evidence gap identified in A3.13.1 §2.2.
- **Proposed Correction:** The snapshot function `fn_generate_source_sensitive_payroll_snapshot` consumes the complete set of calculation inputs sorted deterministically by primary identity:
  1. `employees`: Status, joining date, exit date.
  2. `employee_salaries`: Monthly reference paise, effective date range.
  3. `attendance_days`: Gross minutes, lunch minutes, approved post-18 minutes, net payable minutes, day status counts.
  4. `leave_applications`: Clipped paid and unpaid leave days.
  5. `employee_payroll_adjustments`: Summed additions and deductions.
  6. `payroll_items`: Calculated minute rate, payable minutes, earned paise, net paise.
  Any `INSERT`, `UPDATE`, or `DELETE` to any of these records changes the serialized canonical JSON text string $T$. Because SHA-256 is collision-resistant, $H(T) \neq H(T')$. When `approve_payroll_run` is executed, it recomputes $H(T_{\text{current}})$. If $H(T_{\text{current}}) \neq \text{snapshot\_hash}$, the procedure raises `SQLSTATE P0003 ('STALE_SNAPSHOT')`, strictly preventing approval of stale calculations.
- **Related Approved Decision:** PRD v1.8 §11, DEC-01, DEC-02.
- **Verification Method:** Cryptographic hash sensitivity analysis.
- **Verification Status:** **STATICALLY VERIFIED**.
- **Remaining Risk:** Database engine collation variations across environments; resolved by explicit UTF-8 byte conversion via `convert_to(..., 'UTF8')`.

#### Finding A.8 — SQL-Level Deterministic Canonical Serialization (SDCS) vs. RFC 8785
- **Finding ID:** `DEF-A8`
- **Original A3.13.2 Location:** Section 2.3 lines 397–406.
- **Exact Defect:** Vague claims of RFC 8785 compliance on PostgreSQL `jsonb` without C-extension backing.
- **Root Cause:** Conflating application-level JSON Canonicalization Scheme (RFC 8785) with PostgreSQL internal `jsonb` formatting.
- **Proposed Correction:** Formally retract the claim of certified RFC 8785 compliance. Formally specify the protocol as **SQL Deterministic Canonical Serialization (SDCS)**:
  1. Object keys are explicitly constructed in alphabetical order via `jsonb_build_object()`.
  2. Numerical values are converted to explicit fixed-width strings (`ROUND(..., 6)::text` or integer paise strings).
  3. Timestamps are formatted in ISO 8601 UTC with microsecond precision: `to_char(ts AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`.
  4. Array elements are sorted deterministically by primary identity (`employee_id ASC`) using `jsonb_agg(... ORDER BY employee_id ASC)`.
  5. The resulting text is converted to byte stream via `convert_to(v_canonical_text, 'UTF8')` and digested using `pgcrypto.digest(..., 'sha256')`.
- **Related Approved Decision:** Architectural Decision DEC-01 / Financial Audit Traceability.
- **Verification Method:** Specification review and cryptographic predictability analysis.
- **Verification Status:** **DESIGN-LEVEL SPECIFICATION (SDCS Protocol Defined)**.
- **Remaining Risk:** Client-side re-hashing in non-PostgreSQL runtimes requires identical SDCS formatting libraries.

#### Finding C.5 & C.6 — Durable Two-Phase Provisioning Queue & Non-Atomicity
- **Finding ID:** `DEF-C5`
- **Original A3.13.2 Location:** Section 4.3 lines 633–665.
- **Exact Defect:** Vague claims of distributed atomicity across Supabase Auth (GoTrue HTTP API) and PostgreSQL.
- **Root Cause:** Ignoring the fallacies of distributed computing across separate transactional boundaries.
- **Proposed Correction:**
  1. Formally acknowledge that Supabase GoTrue and PostgreSQL are separate distributed services; **two-phase commit (2PC) is not supported by GoTrue API**.
  2. Implement distributed durability via an idempotent asynchronous provisioning state machine backed by `public.account_provisioning_requests`:
     - States: `PENDING` $\to$ `AUTH_CALLING` $\to$ `AUTH_CREATED` $\to$ `DB_IMPORTING` $\to$ `COMPLETED` (or `FAILED`).

     - Express enqueues request with idempotency key `(organization_id, phone_number, idempotency_key)`.

     - Express calls `public.import_legacy_employee_record(...)` passing `auth_user_id`.
     - If step 4 succeeds, status becomes `COMPLETED`.
  4. Reconciliation: A background worker scans for requests stuck in `AUTH_CREATED` ($> 60\text{ seconds}$). It invokes `import_legacy_employee_record` using the persisted `auth_user_id`. Under no circumstances is a GoTrue user deleted merely because PostgreSQL failed.

- **Verification Method:** State machine state-transition verification.
- **Verification Status:** **STATICALLY VERIFIED**.

```sql
-- ============================================================================
-- 1. update_attendance_day Hardened Stored Procedure
-- ============================================================================
CREATE OR REPLACE PROCEDURE public.update_attendance_day(
  p_organization_id UUID,
  p_attendance_day_id UUID,
  p_day_status public.attendance_day_status_enum,
  p_net_payable_minutes INTEGER,
  p_approved_post18_minutes INTEGER,
  p_admin_user_id UUID,
  p_review_reason TEXT
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_session_org TEXT;
  v_session_user TEXT;
  v_session_role TEXT;
  v_day RECORD;
  v_period RECORD;
BEGIN
  -- 1. Validate caller session context and role
  v_session_org := current_setting('app.current_org_id', true);
  v_session_user := current_setting('app.current_user_id', true);
  v_session_role := current_setting('app.current_user_role', true);

  IF v_session_org IS NULL OR v_session_org::uuid <> p_organization_id THEN
    RAISE EXCEPTION 'Unauthorized tenant context' USING ERRCODE = '42501';
  END IF;

  IF v_session_user IS NULL OR v_session_user::uuid <> p_admin_user_id THEN
    RAISE EXCEPTION 'Actor mismatch with session context' USING ERRCODE = '42501';
  END IF;

  IF v_session_role NOT IN ('ADMIN', 'SUPER_ADMIN') THEN
    RAISE EXCEPTION 'Forbidden: Only Admins can modify attendance records' USING ERRCODE = '42501';
  END IF;

  IF p_review_reason IS NULL OR trim(p_review_reason) = '' THEN
    RAISE EXCEPTION 'A non-blank review reason is mandatory' USING ERRCODE = 'P0001';
  END IF;

  IF p_net_payable_minutes < 0 OR p_net_payable_minutes > 1440 THEN
    RAISE EXCEPTION 'Invalid payable minutes: %', p_net_payable_minutes USING ERRCODE = '22003';
  END IF;

  -- 2. ACQUIRE L1 PERIOD LOCK (Top-Down Global Ordering)
  SELECT pp.id, pp.is_closed INTO v_period
  FROM public.attendance_days ad_lookup
  JOIN public.payroll_periods pp 
    ON pp.organization_id = p_organization_id 
   AND ad_lookup.attendance_date BETWEEN pp.start_date AND pp.end_date
  WHERE ad_lookup.id = p_attendance_day_id
  FOR SHARE OF pp;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % is not mapped to an active payroll period', p_attendance_day_id
      USING ERRCODE = 'P0002';
  END IF;

  IF v_period.is_closed THEN
    RAISE EXCEPTION 'Payroll period is frozen/closed. Mutations strictly forbidden.' USING ERRCODE = '55000';
  END IF;

  -- 3. ACQUIRE L2 ROW LOCK & RE-READ ATTENDANCE DAY
  SELECT id, organization_id, employee_id, attendance_date, day_status, net_payable_minutes,
         first_check_in_at, last_check_out_at
  INTO v_day
  FROM public.attendance_days
  WHERE id = p_attendance_day_id AND organization_id = p_organization_id
  FOR UPDATE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % not found in tenant %', p_attendance_day_id, p_organization_id
      USING ERRCODE = 'P0002';
  END IF;

  -- 4. UPDATE ATTENDANCE DAY WITH ADMIN OVERRIDE
  UPDATE public.attendance_days
  SET day_status = p_day_status,
      net_payable_minutes = p_net_payable_minutes,
      approved_post18_minutes = COALESCE(p_approved_post18_minutes, 0),
      requires_admin_review = FALSE,
      reviewed_by = p_admin_user_id,
      reviewed_at = now(),
      review_reason = trim(p_review_reason),
      updated_at = now()
  WHERE id = p_attendance_day_id;

  -- 5. RECORD IMMUTABLE AUDIT LOG (L4 Append)
  INSERT INTO public.audit_logs (
    organization_id, actor_user_id, actor_role, action, target_table, target_id,
    payload_before, payload_after, reason, created_at

    p_organization_id, p_admin_user_id, v_session_role, 'UPDATE', 'attendance_days', p_attendance_day_id,

    jsonb_build_object('day_status', p_day_status, 'net_payable_minutes', p_net_payable_minutes, 'post18_mins', p_approved_post18_minutes),

-- ============================================================================
-- 2. submit_attendance_correction Hardened Stored Procedure
-- ============================================================================
CREATE OR REPLACE PROCEDURE public.submit_attendance_correction(
  p_organization_id UUID,
  p_attendance_day_id UUID,
  p_employee_id UUID,
  p_action_type public.punch_type_enum,
  p_corrected_timestamp TIMESTAMPTZ,
  p_reason TEXT,
  p_admin_user_id UUID,
  INOUT p_correction_id UUID DEFAULT NULL
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_session_org TEXT;
  v_session_user TEXT;
  v_session_role TEXT;
  v_day RECORD;
  v_period RECORD;
  v_in TIMESTAMPTZ;
  v_out TIMESTAMPTZ;
  v_gross_elapsed INT := 0;
  v_lunch_deducted INT := 0;
  v_net_payable INT := 0;
  v_lunch_start TIMESTAMPTZ;
  v_lunch_end TIMESTAMPTZ;
BEGIN
  -- 1. Validate session context
  v_session_org := current_setting('app.current_org_id', true);
  v_session_user := current_setting('app.current_user_id', true);
  v_session_role := current_setting('app.current_user_role', true);

  IF v_session_org IS NULL OR v_session_org::uuid <> p_organization_id THEN
    RAISE EXCEPTION 'Unauthorized tenant context' USING ERRCODE = '42501';
  END IF;

  IF v_session_user IS NULL OR v_session_user::uuid <> p_admin_user_id THEN
    RAISE EXCEPTION 'Actor mismatch with session context' USING ERRCODE = '42501';
  END IF;

  IF v_session_role NOT IN ('ADMIN', 'SUPER_ADMIN') THEN
    RAISE EXCEPTION 'Forbidden: Only Admins can submit corrections' USING ERRCODE = '42501';
  END IF;

  IF p_reason IS NULL OR trim(p_reason) = '' THEN
    RAISE EXCEPTION 'A non-blank correction reason is mandatory' USING ERRCODE = 'P0001';
  END IF;

  -- 2. ACQUIRE L1 PERIOD LOCK
  SELECT pp.id, pp.is_closed INTO v_period
  FROM public.attendance_days ad_lookup
  JOIN public.payroll_periods pp 
    ON pp.organization_id = p_organization_id 
   AND ad_lookup.attendance_date BETWEEN pp.start_date AND pp.end_date
  WHERE ad_lookup.id = p_attendance_day_id
  FOR SHARE OF pp;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % is not mapped to an active payroll period', p_attendance_day_id
      USING ERRCODE = 'P0002';
  END IF;

  IF v_period.is_closed THEN
    RAISE EXCEPTION 'Payroll period is frozen. Corrections strictly prohibited.' USING ERRCODE = '55000';
  END IF;

  -- 3. ACQUIRE L2 ROW LOCK & RE-READ
  SELECT id, organization_id, employee_id, attendance_date, first_check_in_at, last_check_out_at
  INTO v_day
  FROM public.attendance_days
  WHERE id = p_attendance_day_id AND organization_id = p_organization_id
  FOR UPDATE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % not found in tenant %', p_attendance_day_id, p_organization_id
      USING ERRCODE = 'P0002';
  END IF;

  IF v_day.employee_id <> p_employee_id THEN
    RAISE EXCEPTION 'Attendance day employee mismatch: expected %, got %', v_day.employee_id, p_employee_id
      USING ERRCODE = '42501';
  END IF;

  -- 4. INSERT IMMUTABLE CORRECTION AUDIT ROW
  INSERT INTO public.attendance_corrections (
    organization_id, attendance_day_id, employee_id, action_type, corrected_timestamp, reason,
    previous_state, updated_state, created_by, created_at
  ) VALUES (
    p_organization_id, p_attendance_day_id, p_employee_id, p_action_type, p_corrected_timestamp, trim(p_reason),
    jsonb_build_object('first_check_in_at', v_day.first_check_in_at, 'last_check_out_at', v_day.last_check_out_at),
    jsonb_build_object('action_type', p_action_type, 'corrected_timestamp', p_corrected_timestamp),
    p_admin_user_id, now()
  ) RETURNING id INTO p_correction_id;

  -- 5. RECONCILE EFFECTIVE TIMESTAMPS
  IF p_action_type = 'CHECK_IN' THEN
    v_in := p_corrected_timestamp;
    v_out := v_day.last_check_out_at;
  ELSIF p_action_type = 'CHECK_OUT' THEN
    v_in := v_day.first_check_in_at;
    v_out := p_corrected_timestamp;
  END IF;

  -- 6. RECALCULATE AGGREGATES (DEC-01 & DEC-02 ENFORCED)
  IF v_in IS NOT NULL AND v_out IS NOT NULL AND v_out > v_in THEN
    v_gross_elapsed := ROUND(EXTRACT(EPOCH FROM (v_out - v_in)) / 60.0)::int;
    
    -- DEC-01 Lunch window clipping (13:00 to 14:00 on attendance_date)
    v_lunch_start := v_day.attendance_date + time '13:00:00';
    v_lunch_end := v_day.attendance_date + time '14:00:00';

    IF v_in < v_lunch_end AND v_out > v_lunch_start THEN
      v_lunch_deducted := ROUND(EXTRACT(EPOCH FROM (LEAST(v_out, v_lunch_end) - GREATEST(v_in, v_lunch_start))) / 60.0)::int;
      v_lunch_deducted := GREATEST(0, LEAST(60, v_lunch_deducted));
    ELSE
      v_lunch_deducted := 0;
    END IF;

    -- Net payable minutes capped to pre-18:00 unless approved
    v_net_payable := GREATEST(0, v_gross_elapsed - v_lunch_deducted);
  ELSE
    -- DEC-02: Incomplete or inverted pair produces ZERO payable minutes
    v_gross_elapsed := 0;
    v_lunch_deducted := 0;
    v_net_payable := 0;
  END IF;

  -- 7. UPDATE ATTENDANCE DAY WITH RECALCULATED TOTALS
  UPDATE public.attendance_days
  SET first_check_in_at = v_in,
      last_check_out_at = v_out,
      gross_elapsed_minutes = v_gross_elapsed,
      lunch_deducted_minutes = v_lunch_deducted,
      net_payable_minutes = v_net_payable,
      day_status = CASE WHEN v_net_payable > 0 THEN 'PRESENT'::public.attendance_day_status_enum ELSE 'ABSENT'::public.attendance_day_status_enum END,
      requires_admin_review = FALSE,
      reviewed_by = p_admin_user_id,
      reviewed_at = now(),
      review_reason = trim(p_reason),
      updated_at = now()
  WHERE id = p_attendance_day_id;
END;
$$;
```

```typescript
import { Pool, PoolClient } from 'pg';
import jwt, { JwtPayload } from 'jsonwebtoken';

const dbPool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 50,
  idleTimeoutMillis: 30000,
});

const UUID_V4_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i;
const ALLOWED_ALGORITHMS: jwt.Algorithm[] = ['RS256', 'ES256', 'HS256'];

export async function executeTenantTransaction<T>(
  rawJwtToken: string,
  callback: (client: PoolClient, context: { userId: string; orgId: string; role: string }) => Promise<T>
): Promise<T> {
  // 1. Fail closed on missing JWT configuration
  const algorithm = process.env.SUPABASE_JWT_ALGORITHM as jwt.Algorithm;
  if (!algorithm || !ALLOWED_ALGORITHMS.includes(algorithm)) {
    throw new Error('SECURITY_CONFIG_ERROR: SUPABASE_JWT_ALGORITHM must be explicitly set to RS256, ES256, or HS256');
  }

  const secretOrKey = algorithm.startsWith('RS') || algorithm.startsWith('ES')
    ? process.env.SUPABASE_JWT_PUBLIC_KEY
    : process.env.SUPABASE_JWT_SECRET;

  if (!secretOrKey || (algorithm === 'HS256' && secretOrKey.length < 32)) {
    throw new Error('SECURITY_CONFIG_ERROR: Invalid or insufficiently secure Supabase JWT key/secret');
  }

  if (!process.env.SUPABASE_JWT_ISSUER) {
    throw new Error('SECURITY_CONFIG_ERROR: Missing SUPABASE_JWT_ISSUER environment variable');
  }

  // 2. Cryptographic JWT Verification
  const decoded = jwt.verify(rawJwtToken, secretOrKey, {
    algorithms: [algorithm],
    issuer: process.env.SUPABASE_JWT_ISSUER,
    audience: 'authenticated',
    clockTolerance: 10,
  }) as JwtPayload;

  const authUserId = decoded.sub;
  if (!authUserId || !UUID_V4_REGEX.test(authUserId)) {
    throw new Error('AUTH_FAILED: JWT sub claim is missing or not a valid UUID');
  }

  // 3. Checkout Dedicated Pool Client
  const client = await dbPool.connect();
  let isReleased = false;

  try {
    // 4. Begin Transaction on dedicated client
    await client.query('BEGIN');
    await client.query("SET LOCAL lock_timeout = '3s'; SET LOCAL statement_timeout = '5s';");

    // 5. Resolve Authenticated Tenant Context via Security Definer Function
    const ctxRes = await client.query(
      'SELECT user_id, organization_id, primary_role, is_active, org_active FROM public.resolve_user_auth_context($1)',
      [authUserId]
    );

    const user = ctxRes.rows[0];
    if (!user || user.is_active === false || user.org_active === false) {
      throw new Error('AUTH_DENIED: User or organization account is deactivated');
    }

    // 6. Establish Transaction-Scoped GUC Context
    await client.query(
      `SELECT
         set_config('app.current_user_id', $1, true),
         set_config('app.current_org_id', $2, true),
         set_config('app.current_user_role', $3, true)`,
      [user.user_id, user.organization_id, user.primary_role]
    );

    // 7. Execute Business Operations over the SAME client
    const result = await callback(client, {
      userId: user.user_id,
      orgId: user.organization_id,
      role: user.primary_role,
    });

    // 8. Commit Transaction
    await client.query('COMMIT');
    return result;
  } catch (primaryError) {
    // 9. Rollback without suppressing primary business exception
    try {
      await client.query('ROLLBACK');
    } catch (rollbackError) {
      if (!isReleased) {
        isReleased = true;
        client.release(rollbackError); // Destroy broken socket
      }
      throw primaryError;
    }
    throw primaryError;
  } finally {
    // 10. Defensive connection cleanup
    if (!isReleased) {
      isReleased = true;
      try {
        await client.query('DISCARD SEQUENCES; RESET ALL;');
        client.release();
      } catch (cleanupError) {
        client.release(cleanupError); // Destroy contaminated socket
      }
    }
  }
}
```
- **Related Approved Decision:** DEC-09, Core Security Architecture §2.
- **Verification Method:** Static control-flow and exception-propagation verification.
- **Verification Status:** **STATICALLY VERIFIED (Live Integration Test NOT Executed)**.
- **Remaining Risk:** Pool exhaustion under high concurrent load; mitigated by pool sizing and statement timeouts.

   - Batch synchronization from offline biometric devices during shift changeover windows competes for $L_1$ period shared locks. Bounded timeouts (`lock_timeout = '3s'`) prevent lock queues from exhausting connection pools, but Express retry middleware with exponential backoff and jitter is mandatory.

   - Network timeouts between the Express gateway and Supabase GoTrue can leave provisioning requests in `AUTH_CREATED` state. The asynchronous reconciliation worker must be monitored to ensure orphan user accounts are completed within 5 minutes.
