## 2. SECTION A: PAYROLL SOURCE FREEZE & COMPLETE SNAPSHOT ARCHITECTURE

### 2.1 Complete Freeze Protection Across All 11 Authoritative Sources
In A3.12, freeze guards were defined for 7 tables, leaving 4 tables (`employees`, `leave_types`, `attendance_evidence`, `payroll_periods`) without explicit trigger definitions. Furthermore, date/organization null checks silently returned rather than failing closed.

The table below details freeze protection across all 11 authoritative payroll sources:

| # | Authoritative Table | Covered DML Events | Date / Period Resolution Logic | Freeze Enforcement Rule |
| :--- | :--- | :--- | :--- | :--- |
| **1** | `payroll_periods` | `UPDATE`, `DELETE` | `start_date`, `end_date` (Self) | Prohibit modification of dates, working days, or minutes once `is_closed = TRUE` or run active. |
| **2** | `employees` | `UPDATE`, `DELETE` | `OLD.joining_date`, `NEW.joining_date`, `OLD.exit_date`, `NEW.exit_date` | Prohibit retroactively changing joining/exit dates or status into/out of closed periods. |
| **3** | `attendance_days` | `INSERT`, `UPDATE`, `DELETE` | `OLD.attendance_date`, `NEW.attendance_date` | Prohibit creating, editing, or deleting attendance days in frozen/closed periods. |
| **4** | `attendance_events` | `INSERT`, `UPDATE`, `DELETE` | Resolved from parent `attendance_days` | Prohibit inserting punches or editing events belonging to frozen/closed periods. |
| **5** | `attendance_corrections`| `INSERT`, `UPDATE`, `DELETE` | Resolved from parent `attendance_days` | Prohibit inserting or editing corrections on frozen/closed days. |
| **6** | `attendance_evidence` | `INSERT`, `UPDATE`, `DELETE` | Resolved from `attendance_events` $\to$ `attendance_days` | Prohibit altering verification status or review outcomes for frozen/closed events. |
| **7** | `employee_salaries` | `INSERT`, `UPDATE`, `DELETE` | `[effective_from, COALESCE(effective_to, 'infinity')]` | Prohibit salary contract adjustments overlapping frozen/closed periods. |
| **8** | `leave_applications` | `INSERT`, `UPDATE`, `DELETE` | `[OLD.start_date, OLD.end_date]`, `[NEW.start_date, NEW.end_date]` | Prohibit approving, cancelling, or editing leave requests spanning frozen/closed periods. |
| **9** | `leave_types` | `UPDATE`, `DELETE` | All active periods in organization | Prohibit modifying `is_paid` flag or quota if any active period is frozen/closed. |
| **10**| `holidays` | `INSERT`, `UPDATE`, `DELETE` | `OLD.holiday_date`, `NEW.holiday_date` | Prohibit inserting, editing, or deleting holidays falling within frozen/closed periods. |
| **11**| `employee_payroll_adjustments` | `INSERT`, `UPDATE`, `DELETE` | Target `payroll_period_id` | Prohibit adding or modifying financial adjustments once period is frozen/closed. |

### 2.2 Complete PL/pgSQL Freeze Guard Triggers
The fail-closed master assertion procedure and triggers for all 11 sources are provided below:

```sql
-- ============================================================================
-- MASTER HELPER: Fail-Closed Period Open Assertion
-- ============================================================================
CREATE OR REPLACE FUNCTION public.fn_assert_period_is_open(
  p_organization_id UUID,
  p_date DATE,
  p_table_name TEXT,
  p_operation TEXT
) RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_period_id UUID;
  v_is_closed BOOLEAN;
  v_run_status TEXT;
BEGIN
  -- FAIL-CLOSED: Reject missing context immediately (Fixes A3.12 silent return defect)
  IF p_organization_id IS NULL THEN
    RAISE EXCEPTION 'Payroll freeze assertion failed: organization_id is NULL on table % during %',
      p_table_name, p_operation USING ERRCODE = '22004'; -- null_value_not_allowed
  END IF;

  IF p_date IS NULL THEN
    RAISE EXCEPTION 'Payroll freeze assertion failed: target date is NULL on table % during %',
      p_table_name, p_operation USING ERRCODE = '22004';
  END IF;

  -- Query period status
  SELECT pp.id, pp.is_closed, pr.status
  INTO v_period_id, v_is_closed, v_run_status
  FROM public.payroll_periods pp
  LEFT JOIN public.payroll_runs pr ON pr.payroll_period_id = pp.id 
    AND pr.status IN ('SUBMITTED_FOR_APPROVAL', 'APPROVED', 'PROCESSED')
  WHERE pp.organization_id = p_organization_id
    AND p_date BETWEEN pp.start_date AND pp.end_date
  LIMIT 1;

  IF FOUND THEN
    IF v_is_closed = TRUE THEN
      RAISE EXCEPTION 'Payroll freeze violation: Target date % falls in CLOSED period % (table %, op %)',
        p_date, v_period_id, p_table_name, p_operation USING ERRCODE = '55000';
    END IF;

    IF v_run_status IN ('SUBMITTED_FOR_APPROVAL', 'APPROVED', 'PROCESSED') THEN
      RAISE EXCEPTION 'Payroll freeze violation: Target date % falls in FROZEN period % with status % (table %, op %)',
        p_date, v_period_id, v_run_status, p_table_name, p_operation USING ERRCODE = '55000';
    END IF;
  END IF;
END;
$$;

-- ============================================================================
-- 1. payroll_periods Freeze Guard
-- ============================================================================
CREATE OR REPLACE FUNCTION public.trg_freeze_guard_payroll_periods()
RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, public AS $$
BEGIN
  IF TG_OP = 'DELETE' THEN
    IF OLD.is_closed = TRUE OR EXISTS (SELECT 1 FROM public.payroll_runs WHERE payroll_period_id = OLD.id) THEN
      RAISE EXCEPTION 'Cannot delete payroll_period %: Period is closed or contains payroll runs', OLD.id USING ERRCODE = '55000';
    END IF;
    RETURN OLD;
  ELSIF TG_OP = 'UPDATE' THEN
    IF OLD.is_closed = TRUE AND (NEW.start_date <> OLD.start_date OR NEW.end_date <> OLD.end_date 
        OR NEW.standard_monthly_minutes <> OLD.standard_monthly_minutes OR NEW.scheduled_working_days <> OLD.scheduled_working_days) THEN
      RAISE EXCEPTION 'Cannot alter calendar parameters of closed payroll_period %', OLD.id USING ERRCODE = '55000';
    END IF;
    RETURN NEW;
  END IF;
  RETURN NULL;
END;
$$;

CREATE TRIGGER trg_freeze_payroll_periods
BEFORE UPDATE OR DELETE ON public.payroll_periods
FOR EACH ROW EXECUTE FUNCTION public.trg_freeze_guard_payroll_periods();

-- ============================================================================
-- 2. employees Freeze Guard (Joining/Exit Date Protection)
-- ============================================================================
CREATE OR REPLACE FUNCTION public.trg_freeze_guard_employees()
RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, public AS $$
BEGIN
  IF TG_OP = 'UPDATE' THEN
    IF NEW.joining_date <> OLD.joining_date THEN
      PERFORM public.fn_assert_period_is_open(OLD.organization_id, OLD.joining_date, 'employees', TG_OP);
      PERFORM public.fn_assert_period_is_open(NEW.organization_id, NEW.joining_date, 'employees', TG_OP);
    END IF;
    IF COALESCE(NEW.exit_date, '1900-01-01'::date) <> COALESCE(OLD.exit_date, '1900-01-01'::date) THEN
      IF OLD.exit_date IS NOT NULL THEN
        PERFORM public.fn_assert_period_is_open(OLD.organization_id, OLD.exit_date, 'employees', TG_OP);
      END IF;
      IF NEW.exit_date IS NOT NULL THEN
        PERFORM public.fn_assert_period_is_open(NEW.organization_id, NEW.exit_date, 'employees', TG_OP);
      END IF;
    END IF;
    RETURN NEW;
  ELSIF TG_OP = 'DELETE' THEN
    PERFORM public.fn_assert_period_is_open(OLD.organization_id, OLD.joining_date, 'employees', TG_OP);
    RETURN OLD;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_freeze_employees
BEFORE UPDATE OR DELETE ON public.employees
FOR EACH ROW EXECUTE FUNCTION public.trg_freeze_guard_employees();

-- ============================================================================
-- 7. employee_salaries Freeze Guard (Full OLD and NEW Range Checking)
-- ============================================================================
CREATE OR REPLACE FUNCTION public.trg_freeze_guard_employee_salaries()
RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, public AS $$
DECLARE
  v_emp_org UUID; v_conflict RECORD;
BEGIN
  IF TG_OP IN ('UPDATE', 'DELETE') THEN
    SELECT organization_id INTO v_emp_org FROM public.employees WHERE id = OLD.employee_id;
    -- Check if OLD salary interval intersects any closed/frozen period
    SELECT pp.id INTO v_conflict FROM public.payroll_periods pp
    LEFT JOIN public.payroll_runs pr ON pr.payroll_period_id = pp.id AND pr.status IN ('SUBMITTED_FOR_APPROVAL', 'APPROVED', 'PROCESSED')
    WHERE pp.organization_id = v_emp_org AND (pp.is_closed = TRUE OR pr.id IS NOT NULL)
      AND daterange(pp.start_date, pp.end_date, '[]') && daterange(OLD.effective_from, COALESCE(OLD.effective_to, 'infinity'::date), '[]')
    LIMIT 1;
    IF FOUND THEN RAISE EXCEPTION 'Payroll freeze violation: Cannot alter salary affecting closed/frozen period %', v_conflict.id USING ERRCODE = '55000'; END IF;
  END IF;

  IF TG_OP IN ('INSERT', 'UPDATE') THEN
    SELECT organization_id INTO v_emp_org FROM public.employees WHERE id = NEW.employee_id;
    -- Check if NEW salary interval intersects any closed/frozen period
    SELECT pp.id INTO v_conflict FROM public.payroll_periods pp
    LEFT JOIN public.payroll_runs pr ON pr.payroll_period_id = pp.id AND pr.status IN ('SUBMITTED_FOR_APPROVAL', 'APPROVED', 'PROCESSED')
    WHERE pp.organization_id = v_emp_org AND (pp.is_closed = TRUE OR pr.id IS NOT NULL)
      AND daterange(pp.start_date, pp.end_date, '[]') && daterange(NEW.effective_from, COALESCE(NEW.effective_to, 'infinity'::date), '[]')
    LIMIT 1;
    IF FOUND THEN RAISE EXCEPTION 'Payroll freeze violation: Proposed salary touches closed/frozen period %', v_conflict.id USING ERRCODE = '55000'; END IF;
    RETURN NEW;
  END IF;
  RETURN OLD;
END;
$$;
```

### 2.3 Source-Sensitive, Versioned Payroll Snapshot & Storage Specification
In A3.12, the snapshot function serialized only calculated output line items (`payroll_items`). In A3.13, the snapshot protocol captures both **Source Input Telemetry** and **Derived Line Items**:

```

│ CANONICAL PAYROLL SNAPSHOT (JSONB)                                    │
│ {                                                                      │
│   "snapshot_version": "2.0",                                           │
│   "period_header": { org_id, period_id, start_date, end_date, ... },   │
│   "source_inputs": [                                                   │
│     { employee_id, joining_date, salary_paise, scheduled_minutes,      │
│       worked_minutes, lunch_deducted_minutes, approved_post18_minutes, │
│       paid_leave_days, unpaid_leave_days, adjustments_paise }          │
│   ],                                                                   │
│   "calculated_outputs": [                                              │
│     { employee_id, earned_salary_paise, total_adjustments_paise,        │
│       total_deductions_paise, net_salary_paise }                       │
│   ]                                                                    │
│ }                                                                      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ UTF-8 Conversion & SHA-256 Digest
                                    ▼
```

The snapshot and cryptographic hash are persisted directly in `public.payroll_runs`:

```sql
  p_approver_id UUID
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_run RECORD;
  v_current_snapshot JSONB;
  v_current_hash TEXT;
BEGIN
  -- 1. Fetch run details
  SELECT pr.id, pr.payroll_period_id, pr.status, pr.source_snapshot_hash, pp.organization_id
  INTO v_run
  FROM public.payroll_runs pr
  JOIN public.payroll_periods pp ON pp.id = pr.payroll_period_id
  WHERE pr.id = p_payroll_run_id;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Payroll run % not found', p_payroll_run_id USING ERRCODE = 'P0002';
  END IF;

  IF v_run.status <> 'SUBMITTED_FOR_APPROVAL' THEN
    RAISE EXCEPTION 'Invalid transition: Run % has status %, must be SUBMITTED_FOR_APPROVAL',
      p_payroll_run_id, v_run.status USING ERRCODE = '55000';
  END IF;

  -- 2. ACQUIRE EXCLUSIVE PERIOD LOCK (Enforces L1 hierarchy)
  PERFORM id FROM public.payroll_periods WHERE id = v_run.payroll_period_id FOR UPDATE;

  -- 3. RECOMPILE SNAPSHOT & VALIDATE STALENESS
  v_current_snapshot := public.fn_generate_source_sensitive_payroll_snapshot(p_payroll_run_id);
  v_current_hash := v_current_snapshot->>'sha256_hash';

  IF v_current_hash <> v_run.source_snapshot_hash THEN
    RAISE EXCEPTION 'PAYROLL_STALE_SNAPSHOT: Underlying attendance, leave, or compensation data was modified since calculation. Recompilation required.'
      USING ERRCODE = 'P0004';
  END IF;

  -- 4. COMMIT APPROVAL TRANSITION
  UPDATE public.payroll_runs
  SET status = 'APPROVED',
      approved_by = p_approver_id,
      approved_at = now(),
      updated_at = now()
  WHERE id = p_payroll_run_id;

  -- 5. CLOSE PAYROLL PERIOD
  UPDATE public.payroll_periods
  SET is_closed = TRUE
  WHERE id = v_run.payroll_period_id;
END;
$$;
```

```sql
CREATE OR REPLACE FUNCTION public.trg_assert_tenant_and_actor_integrity()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_session_org_id TEXT;
  v_session_user_id TEXT;
  v_target_org UUID;
BEGIN
  -- Read transactional session GUCs
  v_session_org_id  := current_setting('app.current_org_id', true);
  v_session_user_id := current_setting('app.current_user_id', true);

  -- FAIL-CLOSED: Reject unauthenticated mutations across all operations
  IF v_session_org_id IS NULL OR v_session_org_id = '' THEN
    RAISE EXCEPTION 'Access denied: Transactional session variable app.current_org_id is unset (SQLSTATE 42501)'
      USING ERRCODE = 'insufficient_privilege';
  END IF;

  IF v_session_user_id IS NULL OR v_session_user_id = '' THEN
    RAISE EXCEPTION 'Access denied: Transactional session variable app.current_user_id is unset (SQLSTATE 42501)'
      USING ERRCODE = 'insufficient_privilege';
  END IF;

  -- Resolve target organization depending on operation
  IF TG_OP = 'DELETE' THEN
    IF TG_TABLE_NAME IN ('offices', 'departments', 'users', 'employees', 'attendance_days', 
                         'leave_types', 'holidays', 'payroll_periods', 'audit_logs') THEN
      v_target_org := OLD.organization_id;
    END IF;
  ELSE
    IF TG_TABLE_NAME IN ('offices', 'departments', 'users', 'employees', 'attendance_days', 
                         'leave_types', 'holidays', 'payroll_periods', 'audit_logs') THEN
      v_target_org := NEW.organization_id;
    END IF;
  END IF;

  -- Enforce Tenant Boundary
  IF v_target_org IS NOT NULL AND v_target_org::text <> v_session_org_id THEN
    RAISE EXCEPTION 'Cross-tenant violation: Target organization % does not match session % (SQLSTATE 42501)',
      v_target_org, v_session_org_id USING ERRCODE = 'insufficient_privilege';
  END IF;

  RETURN COALESCE(NEW, OLD);
END;
$$;
```

### 4.2 Hardened Import Procedure with Database Role Verification

```sql
CREATE OR REPLACE PROCEDURE public.import_legacy_employee_record(
  p_organization_id UUID,
  p_auth_user_id UUID, -- Durable GoTrue UUID (DEC-09 Compliant)
  p_phone_number VARCHAR(15),
  p_office_id UUID,
  p_department_id UUID,
  p_designation_id UUID,
  p_first_name VARCHAR(100),
  p_last_name VARCHAR(100),
  p_date_of_birth DATE,
  p_gender public.gender_enum,
  p_residential_address TEXT,
  p_joining_date DATE,
  p_base_salary_paise BIGINT,
  p_legacy_code_suffix INTEGER DEFAULT NULL, -- Existing legacy numeric code for safe counter sync
  INOUT p_employee_id UUID DEFAULT NULL,
  INOUT p_employee_code VARCHAR(20) DEFAULT NULL
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_session_user_id TEXT;
  v_session_org_id TEXT;
  v_caller_role_count INT;
  v_user_id UUID;
  v_next_num INTEGER;
  v_existing_emp_id UUID;
  v_org_active BOOLEAN;
BEGIN
  -- 1. READ TRANSACTIONAL GUCs
  v_session_user_id := current_setting('app.current_user_id', true);
  v_session_org_id  := current_setting('app.current_org_id', true);

  -- 2. REJECT NULL CALLER CONTEXT (Fixes A3.12 defect)
  IF v_session_org_id IS NULL OR v_session_org_id = '' THEN
    RAISE EXCEPTION 'Unauthorized: Caller organization context app.current_org_id is missing (SQLSTATE 42501)'
      USING ERRCODE = 'insufficient_privilege';
  END IF;

  IF v_session_user_id IS NULL OR v_session_user_id = '' THEN
    RAISE EXCEPTION 'Unauthorized: Caller user context app.current_user_id is missing (SQLSTATE 42501)'
      USING ERRCODE = 'insufficient_privilege';
  END IF;

  -- 3. VERIFY ROLE DIRECTLY AGAINST DATABASE TABLE (Never trust GUC alone)
  SELECT COUNT(*) INTO v_caller_role_count
  FROM public.user_roles ur
  JOIN public.users u ON u.id = ur.user_id
  WHERE u.id = v_session_user_id::uuid
    AND ur.role IN ('MAINTENANCE_ADMIN', 'SUPER_ADMIN');

  IF v_caller_role_count = 0 THEN
    RAISE EXCEPTION 'Unauthorized: Database user % lacks MAINTENANCE_ADMIN or SUPER_ADMIN role (SQLSTATE 42501)',
      v_session_user_id USING ERRCODE = 'insufficient_privilege';
  END IF;

  -- 4. ASSERT TENANT BOUNDARY
  IF v_session_org_id <> p_organization_id::text THEN
    -- Allow super-admin override only if verified in user_roles
    IF NOT EXISTS (SELECT 1 FROM public.user_roles WHERE user_id = v_session_user_id::uuid AND role = 'SUPER_ADMIN') THEN
      RAISE EXCEPTION 'Tenant isolation violation: Caller org % cannot import into org %',
        v_session_org_id, p_organization_id USING ERRCODE = '42501';
    END IF;
  END IF;

  -- 5. ASSERT ORGANIZATION ACTIVE STATUS
  SELECT is_active INTO v_org_active FROM public.organizations WHERE id = p_organization_id;
  IF NOT FOUND OR v_org_active = FALSE THEN
    RAISE EXCEPTION 'Target organization % does not exist or is deactivated', p_organization_id USING ERRCODE = '55000';
  END IF;

  -- 6. RESOLVE OR CREATE USER RECORD (Linked to GoTrue auth_user_id)
  SELECT id INTO v_user_id FROM public.users WHERE organization_id = p_organization_id AND auth_user_id = p_auth_user_id;

  IF v_user_id IS NULL THEN
    INSERT INTO public.users (
      organization_id,
      auth_user_id,
      phone_number,
      synthetic_email,
      must_change_password,
      is_active,
      created_at,
      updated_at
    ) VALUES (
      p_organization_id,
      p_auth_user_id,
      p_phone_number,
      p_auth_user_id::text || '@auth.hrms.internal', -- REC-01 Pending PO Signoff
      TRUE,
      TRUE,
      now(),
      now()
    ) RETURNING id INTO v_user_id;

    INSERT INTO public.user_roles (user_id, role) VALUES (v_user_id, 'EMPLOYEE');
  END IF;

  -- 7. ENFORCE 0..1:1 USER-TO-EMPLOYEE RELATIONSHIP
  SELECT id INTO v_existing_emp_id FROM public.employees WHERE user_id = v_user_id;
  IF v_existing_emp_id IS NOT NULL THEN
    RAISE EXCEPTION 'Integrity violation: User % is already linked to employee %', v_user_id, v_existing_emp_id USING ERRCODE = '23505';
  END IF;

  -- 8. SAFE COUNTER SYNCHRONIZATION & ALLOCATION (ERD lines 522-545 compliant)
  INSERT INTO public.organization_employee_counters (organization_id, last_employee_number, updated_at)
  VALUES (p_organization_id, COALESCE(p_legacy_code_suffix, 1), now())
  ON CONFLICT (organization_id) DO UPDATE
  SET last_employee_number = GREATEST(organization_employee_counters.last_employee_number, COALESCE(p_legacy_code_suffix, 0)) + 1,
      updated_at = now()
  RETURNING last_employee_number INTO v_next_num;

  IF v_next_num > 999999 THEN
    RAISE EXCEPTION 'Counter overflow: Maximum employee limit reached for org %', p_organization_id USING ERRCODE = '22003';
  END IF;

  -- Format: EMP001...EMP999...EMP1000... (Zero truncation)
  p_employee_code := 'EMP' || TO_CHAR(v_next_num, 'FM000');

  -- 9. INSERT EMPLOYEE RECORD
  INSERT INTO public.employees (
    organization_id,
    user_id,
    office_id,
    department_id,
    designation_id,
    employee_code,
    first_name,
    last_name,
    date_of_birth,
    gender,
    residential_address,
    joining_date,
    employment_status,
    created_at,
    updated_at
  ) VALUES (
    p_organization_id,
    v_user_id,
    p_office_id,
    p_department_id,
    p_designation_id,
    p_employee_code,
    p_first_name,
    p_last_name,
    p_date_of_birth,
    p_gender,
    p_residential_address,
    p_joining_date,
    'CONFIRMED',
    now(),
    now()
  ) RETURNING id INTO p_employee_id;

  -- 10. INITIAL SALARY ASSIGNMENT
  IF p_base_salary_paise IS NOT NULL AND p_base_salary_paise >= 0 THEN
    INSERT INTO public.employee_salaries (
      employee_id,
      monthly_salary_reference_paise,
      effective_from,
      created_by,
      created_at
    ) VALUES (
      p_employee_id,
      p_base_salary_paise,
      p_joining_date,
      v_user_id,
      now()
    );
  END IF;
END;
$$;
```

## 5. SECTION D: ENFORCEABLE DATABASE WRITE BOUNDARIES & LOCK ORDERING

### 5.1 Enforceable Database Write Boundary (Resolving Direct DML Bypass)
To prevent ad-hoc queries from bypassing top-down locking ($L_1 \prec L_2 \prec L_3 \prec L_4$):
1. **Revocation of Direct DML:** Direct `INSERT`, `UPDATE`, and `DELETE` on operational tables (`attendance_days`, `attendance_events`, `attendance_corrections`, `payroll_runs`, `payroll_items`) are **explicitly revoked** from the application connection role `hrms_app_user`.
2. **Mandatory Stored Procedure Write Boundary:** All mutations **must execute via dedicated stored procedures** (`record_attendance_punch`, `update_attendance_day`, `submit_attendance_correction`, `approve_payroll_run`).
3. **Guaranteed $L_1$ Lock Acquisition:** Every stored procedure executes Statement 1:
   ```sql
   SELECT id FROM public.payroll_periods WHERE ... FOR SHARE; -- (or FOR UPDATE)
   ```
   *prior to issuing any DML on attendance tuples.*

```sql
CREATE OR REPLACE PROCEDURE public.record_attendance_punch(
  p_organization_id UUID,
  p_employee_id UUID,
  p_office_id UUID,
  p_event_type public.punch_type_enum,
  p_device_timestamp TIMESTAMPTZ,
  p_latitude NUMERIC,
  p_longitude NUMERIC,
  p_accuracy_meters NUMERIC,

  v_work_date DATE;
  v_period_id UUID;
BEGIN

  SELECT id INTO v_period_id
  FROM public.payroll_periods
  WHERE organization_id = p_organization_id
    AND v_work_date BETWEEN start_date AND end_date
  FOR SHARE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Target work date % is not mapped to any configured payroll period', v_work_date USING ERRCODE = 'P0001';
  END IF;

  ) VALUES (
    p_organization_id, p_employee_id, p_office_id, v_work_date, 'PRESENT', now(), now()
  )

  SET updated_at = now()

  ) VALUES (

    p_latitude, p_longitude, p_accuracy_meters, p_distance_meters, p_is_within_geofence, now()
  ) RETURNING id INTO p_punch_id;
```

```sql
AS $$
BEGIN
  -- Rejects NULL input
  IF p_auth_user_id IS NULL THEN
    RAISE EXCEPTION 'Authentication resolution failed: p_auth_user_id cannot be NULL' USING ERRCODE = '22004';
  END IF;

  RETURN QUERY
  SELECT
    u.id AS user_id,
    u.organization_id,
    -- Deterministic role precedence: SUPER_ADMIN > MAINTENANCE_ADMIN > ADMIN > EMPLOYEE
    COALESCE((
      SELECT ur.role::text
      FROM public.user_roles ur
      WHERE ur.user_id = u.id
      ORDER BY CASE ur.role
        WHEN 'SUPER_ADMIN' THEN 1
        WHEN 'MAINTENANCE_ADMIN' THEN 2
        WHEN 'ADMIN' THEN 3
        WHEN 'EMPLOYEE' THEN 4
        ELSE 5 END ASC
      LIMIT 1
    ), 'EMPLOYEE') AS primary_role,
    u.is_active,
    o.is_active AS org_active
  FROM public.users u
  JOIN public.organizations o ON o.id = u.organization_id
  WHERE u.auth_user_id = p_auth_user_id;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Authentication resolution failed: User with auth_user_id % not found', p_auth_user_id
      USING ERRCODE = 'P0002';
  END IF;
END;
$$;
```

### 6.2 Production-Grade Express Transaction Wrapper (Preventing Double Release)

```typescript
import { Pool, PoolClient } from 'pg';
import jwt, { JwtPayload } from 'jsonwebtoken';

const dbPool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 50,
  idleTimeoutMillis: 30000,
});

export async function runInTenantTransaction<T>(
  rawJwtToken: string,
  callback: (client: PoolClient, authContext: { userId: string; orgId: string; role: string }) => Promise<T>
): Promise<T> {
  // 1. Cryptographically verify JWT using RS256 and Supabase Public Key
  const decoded = jwt.verify(rawJwtToken, process.env.SUPABASE_JWT_PUBLIC_KEY!, {
    algorithms: ['RS256'],
    issuer: process.env.SUPABASE_JWT_ISSUER,
    audience: 'authenticated',
  }) as JwtPayload;

  const authUserId = decoded.sub;
  if (!authUserId) {
    throw new Error('AUTH_FAILED: JWT sub claim missing');
  }

  // 2. Checkout dedicated client from pool
  const client = await dbPool.connect();
  let isClientReleased = false;

  try {
    // 3. Begin atomic transaction
    await client.query('BEGIN');

    // 4. Resolve verified context via SECURITY DEFINER procedure
    const contextRes = await client.query(
      'SELECT user_id, organization_id, primary_role, is_active, org_active FROM public.resolve_user_auth_context($1)',
      [authUserId]
    );

    const user = contextRes.rows[0];
    if (!user || user.is_active === false || user.org_active === false) {
      throw new Error('AUTH_DEACTIVATED: User or tenant account is deactivated');
    }

    // 5. Establish local transaction-scoped GUCs
    await client.query(
      `SELECT
         set_config('app.current_user_id', $1, true),
         set_config('app.current_org_id', $2, true),
         set_config('app.current_user_role', $3, true)`,
      [user.user_id, user.organization_id, user.primary_role]
    );

    // 6. Execute protected callback over the EXACT SAME client
    const result = await callback(client, {
      userId: user.user_id,
      orgId: user.organization_id,
      role: user.primary_role,
    });

    // 7. Commit transaction
    await client.query('COMMIT');
    return result;
  } catch (error) {
    // 8. Rollback on failure
    try {
      await client.query('ROLLBACK');
    } catch (rollbackErr) {
      // If rollback fails, destroy connection completely
      if (!isClientReleased) {
        isClientReleased = true;
        client.release(rollbackErr);
      }
      throw error;
    }
    throw error;
  } finally {
    // 9. Defensive cleanup ensuring client is NEVER released twice
    if (!isClientReleased) {
      isClientReleased = true;
      try {
        await client.query('DISCARD SEQUENCES; RESET ALL;');
        client.release();
      } catch (cleanupErr) {
        // Destroy client on reset failure to prevent socket contamination
        client.release(cleanupErr);
      }
    }
  }
}
```
