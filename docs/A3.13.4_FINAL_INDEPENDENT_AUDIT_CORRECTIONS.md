### Finding A1: Leave-Period Boundary & Scheduled-Working-Day Deductions
- **Finding ID:** `DEF-14.A1`
- **Original Defect in A3.13.3:** Section 2 (`DEF-A3`) calculated leave deductions as `(LEAST(la.end_date, v_period.end_date) - GREATEST(la.start_date, v_period.start_date) + 1) * 420`. This counted raw calendar days, erroneously deducting 420 minutes for Sundays (statutory weekly offs) and declared public holidays falling within a multi-day leave application.
- **Root Cause:** Conflating elapsed calendar duration with eligible scheduled working days.
- **Affected SQL:** `fn_generate_source_sensitive_payroll_snapshot` and `fn_execute_period_calculation_engine`.
- **Corrected Design & SQL:**
  The eligible working days within a clipped leave period must be calculated strictly against the approved Monday–Saturday working calendar, excluding Sundays (`ISODOW <> 7`) and non-working public holidays (`is_optional = FALSE`):
  ```sql
  -- Eligible scheduled leave days calculation excluding weekly offs and declared holidays
  WITH leave_date_series AS (
    SELECT
      la.id AS leave_application_id,
      la.employee_id,
      d::date AS calendar_date
    FROM public.leave_applications la
    CROSS JOIN LATERAL generate_series(
      GREATEST(la.start_date, v_period.start_date),
      LEAST(la.end_date, v_period.end_date),
      '1 day'::interval
    ) AS d
    WHERE la.status = 'APPROVED'
      AND la.organization_id = v_period.organization_id
      AND la.start_date <= v_period.end_date
      AND la.end_date >= v_period.start_date
  ),
  eligible_leave_days AS (
    SELECT
      lds.employee_id,
      COUNT(*) AS scheduled_leave_days
    FROM leave_date_series lds
    LEFT JOIN public.holidays h 
      ON h.organization_id = v_period.organization_id 
     AND h.holiday_date = lds.calendar_date
     AND h.is_optional = FALSE
    WHERE EXTRACT(ISODOW FROM lds.calendar_date) <> 7 -- Exclude Sundays
      AND h.id IS NULL                                -- Exclude Public Holidays
    GROUP BY lds.employee_id
  )
  SELECT COALESCE(eld.scheduled_leave_days * 420, 0)::int
  INTO v_unpaid_leave_mins
  FROM eligible_leave_days eld
  WHERE eld.employee_id = v_emp.employee_id;
  ```
- **Relationship to Approved Decisions:** PRD v1.8 §9 line 280; PRD v1.8 §10 lines 287–290; PRD v1.8 §11 line 297.
- **Remaining Risks:** Half-day leave policies require decimal scheduled day representation in Phase 3.
- **Evidence Classification:** `STATICALLY VERIFIED`.

### Finding A2: Complete Daily Partition & Non-Double-Deduction Invariant
- **Finding ID:** `DEF-14.A2`
- **Original Defect in A3.13.3:** Absence minutes and unpaid leave minutes were accumulated independently without a formal partitioning invariant, creating risks where a day on approved leave could also be counted as unauthorized absence, deducting the employee twice.
- **Root Cause:** Lack of an explicit disjoint partition across daily attendance states.
- **Corrected Design & Proof:**
  For any employee $e$ on any calendar date $d \in [\text{start\_date}, \text{end\_date}]$, the day status $S(e, d)$ belongs to exactly ONE mutually exclusive set:
  $$\text{Calendar Date } d \implies \begin{cases}
  \text{WEEKLY\_OFF} & \text{if } \text{ISODOW}(d) = 7 \\
  \text{PUBLIC\_HOLIDAY} & \text{if } \exists h \in \text{holidays}: h.\text{date} = d \land \neg h.\text{is\_optional} \\
  \text{ON\_LEAVE} & \text{if } \exists l \in \text{leave\_apps}: l.\text{status} = \text{'APPROVED'} \land d \in [l.\text{start}, l.\text{end}] \\
  \text{PRESENT} & \text{if } \exists a \in \text{attendance\_days}: a.\text{net\_payable\_minutes} > 0 \\
  \text{ABSENT} & \text{otherwise (unauthorized absence on scheduled working day)}
  \end{cases}$$
  **Financial Proof of Single Derivation:**
  Because payroll is strictly calculated using positive minute accumulation:
  $$\text{Earned Salary (Paise)} = M_{\text{payable}} \times \text{Minute Rate}$$
  Absent minutes and leave minutes are not deducted from base salary; they simply do not accrue payable minutes. The payslip reports:
  $$M_{\text{unpaid\_absence}} = \text{COUNT}(\text{ABSENT days}) \times 420$$
  $$M_{\text{unpaid\_leave}} = \text{COUNT}(\text{ON\_LEAVE eligible days}) \times 420$$
  $$M_{\text{scheduled}} = M_{\text{payable}} + M_{\text{unpaid\_absence}} + M_{\text{unpaid\_leave}} + M_{\text{unapproved\_deficit}}$$
  Total deductions are strictly reserved for external advances, recoveries, or statutory withholding (`employee_payroll_adjustments`). Double deduction is mathematically impossible.
- **Relationship to Approved Decisions:** PRD v1.8 §9, §10, §11.
- **Remaining Risks:** Unpaired check-ins pending review at month end; resolved by mandatory admin review before payroll freeze.
- **Evidence Classification:** `STATICALLY VERIFIED`.

### Finding A3: Full Engine Reconciliation with Approved Product Invariants
- **Finding ID:** `DEF-14.A3`
- **Original Defect in A3.13.3:** Engine logic did not strictly enforce that post-18:00 work is paid at exactly 1.0x ordinary rate and did not exclude Sundays/holidays from scheduled monthly minutes ($M_{\text{std}}$).
- **Root Cause:** Hardcoding month-level scheduled days without dynamically evaluating holiday records.
- **Corrected Specification:**
  1. **Standard Scheduled Working Days ($N_{\text{sched}}$):**
     $$N_{\text{sched}} = \sum_{d = \text{start\_date}}^{\text{end\_date}} \left[ \mathbb{I}(\text{ISODOW}(d) \neq 7) \times \mathbb{I}(d \notin \text{holidays}) \right]$$
  2. **Standard Monthly Scheduled Minutes ($M_{\text{std}}$):**
     $$M_{\text{std}} = N_{\text{sched}} \times 420\text{ minutes}$$
  3. **High-Precision Minute Rate ($R_{\text{min}}$):**
     $$R_{\text{min}} = \text{ROUND}\left( \frac{\text{monthly\_salary\_reference\_paise}}{M_{\text{std}}}, 6 \right) \quad (\text{stored as } \texttt{NUMERIC(14,6)})$$
  4. **Post-18:00 Overtime Rate:**
     Paid at strictly $1.0\times$ minute rate ($R_{\text{post18}} = R_{\text{min}}$). No overtime premium or multiplier exists under approved PRD v1.8 baseline.
  5. **DEC-01 & DEC-02 Engine Integration:**
     Sessions crossing 13:00–14:00 deduct exactly overlapping minutes (max 60). Sessions with missing check-in or missing check-out produce $M_{\text{payable}} = 0$.
- **Relationship to Approved Decisions:** PRD v1.8 §11, DEC-01, DEC-02.
- **Remaining Risks:** High fractional paise rounding across an entire workforce; resolved by half-up rounding to nearest paise on individual line items (`ROUND(...)`).
- **Evidence Classification:** `STATICALLY VERIFIED`.

### Finding A6: Definitive SQL Deterministic Canonical Serialization (SDCS) Protocol
- **Finding ID:** `DEF-14.A6`
- **Original Defect in A3.13.3:** Claimed `jsonb_build_object::text` guarantees canonical formatting. PostgreSQL documentation states that while `jsonb` normalizes key order in memory, `::text` serialization formatting of numbers, escaping, and whitespace can vary across PostgreSQL major versions and client locales.
- **Root Cause:** Over-reliance on internal database type casts for cryptographic hashing.
- **Corrected Specification:**
  The **SDCS Protocol (Version 2.1)** enforces strict wire-level determinism prior to cryptographic hashing:
  1. **Strict Alphabetical Key Ordering:** Every JSON object is generated via explicit nesting where keys are strictly ordered by ASCII code points:
     `{"a_field": ..., "b_field": ..., "c_field": ...}`.
  2. **Explicit Text-Casting for Numbers:** Floating-point numbers are prohibited. All monetary figures are formatted as integer strings (`amount_paise::text`). All rates are formatted to exactly 6 fixed decimal places (`to_char(rate, 'FM999999990.000000')`).
  3. **Timestamp Normalization:** All dates and timestamps are formatted in ISO 8601 UTC with explicit microsecond precision:
     `to_char(ts AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`.
  4. **Deterministic Array Sorting:** Array elements are aggregated using `jsonb_agg(... ORDER BY primary_key ASC)`.
  5. **Standardized UTF-8 Byte Stream:** The resulting string is cast to byte stream via `convert_to(canonical_str, 'UTF8')`.
  6. **Digest Generation:** Hashed via `pgcrypto.digest(byte_stream, 'sha256')` and encoded as lowercase hex string (`encode(..., 'hex')`).
- **Relationship to Approved Decisions:** Architectural Integrity Baseline.
- **Remaining Risks:** Database collation differences affecting string sorting; resolved by explicitly ordering using binary `COLLATE "C"`.
- **Evidence Classification:** `DESIGN-LEVEL SPECIFICATION`.

### Finding A7: Concurrency Control Between Snapshot, Approval and Freeze
- **Finding ID:** `DEF-14.A7`
- **Original Defect in A3.13.3:** Lack of an explicit transaction lock trace proving that source changes cannot slip in between snapshot verification and payroll freeze.
- **Root Cause:** Concurrency edge-case analysis gap.
- **Corrected Design & Concurrency Trace:**
  ```
  TRANSACTION 1 (Admin Approval: approve_payroll_run)
  ─────────────────────────────────────────────────────────────────────────────
  T1.1: BEGIN;
  T1.2: SELECT id FROM payroll_periods WHERE id = p_period_id FOR UPDATE;
        ──> Acquires Exclusive Row Lock on period.
        ──> Blocks all concurrent attendance writes attempting FOR SHARE period lock.
  T1.3: Regenerate SDCS Snapshot Hash: H_live := fn_generate_source_sensitive_payroll_snapshot(p_run_id);
  T1.4: Assert H_live = run.snapshot_hash;
        ──> If mismatched: RAISE EXCEPTION 'STALE_SNAPSHOT' (Rolls back T1).
  T1.5: UPDATE payroll_periods SET is_closed = TRUE, closed_at = now(), closed_by = p_admin_id;
        ──> Database freeze triggers immediately activate fail-closed state.
  T1.6: UPDATE payroll_runs SET status = 'APPROVED', approved_by = p_admin_id, approved_at = now();
  T1.7: COMMIT;
        ──> Lock released only after freeze is permanently committed.
  ```
  Any concurrent attendance punch or correction trying to commit between T1.2 and T1.7 blocks on the `FOR SHARE` lock. Once T1 commits, the concurrent transaction unblocks, reads `is_closed = TRUE`, and is aborted by `trg_freeze_guard_*` with `SQLSTATE 55000`. Race conditions are mathematically eliminated.
- **Relationship to Approved Decisions:** PRD v1.8 §11.
- **Remaining Risks:** Transaction timeout during snapshot generation on very large tenants ($> 10,000$ employees); solved by chunked aggregation.
- **Evidence Classification:** `STATICALLY VERIFIED`.

### Finding B6: True Actor Integrity Verification in Triggers
- **Finding ID:** `DEF-14.B6`
- **Original Defect in A3.13.3:** `trg_assert_tenant_and_actor_integrity()` only checked `v_current_user_id IS NOT NULL`. It did not verify that the asserted user ID matched the row's audit fields (`created_by`, `updated_by`, `reviewed_by`), allowing a malicious caller to impersonate another user in audit columns.
- **Root Cause:** Incomplete audit column binding in trigger logic.
- **Corrected PL/pgSQL Function:**
  ```sql
  CREATE OR REPLACE FUNCTION public.trg_assert_tenant_and_actor_integrity()
  RETURNS TRIGGER
  LANGUAGE plpgsql
  SECURITY DEFINER
  SET search_path = pg_catalog, public
  AS $$
  DECLARE
    v_session_org TEXT;
    v_session_user TEXT;
    v_session_role TEXT;
    v_row_org_id UUID;
    v_row_actor_id UUID;
  BEGIN
    -- Read asserted session GUCs
    v_session_org := current_setting('app.current_org_id', true);
    v_session_user := current_setting('app.current_user_id', true);
    v_session_role := current_setting('app.current_user_role', true);

    -- 1. Fail closed on missing context
    IF v_session_org IS NULL OR trim(v_session_org) = '' THEN
      RAISE EXCEPTION 'Access Denied: Unset tenant context (app.current_org_id)' USING ERRCODE = '42501';
    END IF;

    IF v_session_user IS NULL OR trim(v_session_user) = '' THEN
      RAISE EXCEPTION 'Access Denied: Unset actor context (app.current_user_id)' USING ERRCODE = '42501';
    END IF;

    -- 2. Resolve row tenant ID
    IF TG_OP = 'DELETE' THEN
      v_row_org_id := OLD.organization_id;
    ELSE
      v_row_org_id := NEW.organization_id;
    END IF;

    IF v_row_org_id IS DISTINCT FROM v_session_org::uuid THEN
      RAISE EXCEPTION 'Cross-Tenant Violation: Row org % does not match session %', v_row_org_id, v_session_org
        USING ERRCODE = '42501';
    END IF;

    -- 3. Assert Actor Integrity on Insert / Update
    IF TG_OP = 'INSERT' THEN
      -- If table has created_by column, enforce matching session user
      IF TG_TABLE_NAME IN ('attendance_corrections', 'employee_salaries', 'leave_applications', 'payment_records') THEN
        IF NEW.created_by IS DISTINCT FROM v_session_user::uuid THEN
          RAISE EXCEPTION 'Actor Spoofing Detected: created_by (%) does not match authenticated user (%)',
            NEW.created_by, v_session_user USING ERRCODE = '42501';
        END IF;
      END IF;
    ELSIF TG_OP = 'UPDATE' THEN
      -- If table has reviewed_by column and review is occurring, enforce matching session user
      IF TG_TABLE_NAME = 'attendance_days' AND NEW.reviewed_by IS NOT NULL AND OLD.reviewed_by IS DISTINCT FROM NEW.reviewed_by THEN
        IF NEW.reviewed_by IS DISTINCT FROM v_session_user::uuid THEN
          RAISE EXCEPTION 'Reviewer Spoofing Detected: reviewed_by (%) does not match authenticated user (%)',
            NEW.reviewed_by, v_session_user USING ERRCODE = '42501';
        END IF;
      END IF;
    END IF;

    RETURN CASE WHEN TG_OP = 'DELETE' THEN OLD ELSE NEW END;
  END;
  $$;
  ```
- **Relationship to Approved Decisions:** Core Security Architecture §3.
- **Remaining Risks:** Stored procedures bypassing triggers; resolved by attaching triggers `BEFORE INSERT OR UPDATE OR DELETE` across all mutable tables.
- **Evidence Classification:** `STATICALLY VERIFIED`.

### Finding B7: Threat Model for Database GUC Assertion vs. Authenticated Identity
- **Finding ID:** `DEF-14.B7`
- **Original Defect in A3.13.3:** Prose conflated database GUC variables with cryptographic caller authentication.
- **Root Cause:** Architectural oversimplification of multi-tenant security layers.
- **Threat Model Analysis:**
  - *Threat Vector:* If an attacker achieves arbitrary SQL execution as runtime role `hrms_app_user` (e.g. via an unescaped SQL query), they can execute `SELECT set_config('app.current_org_id', 'victim_org_uuid', false);` and attempt to read or modify victim tenant data.
  - *Why GUCs Alone Are Not an Authentication Boundary:* In PostgreSQL, GUCs are session-level key-value strings that any connected client can overwrite unless explicitly restricted.
  - *Engine-Level Defense-in-Depth:*
    1. **Direct DML Revocation:** `hrms_app_user` possesses zero `INSERT`, `UPDATE`, `DELETE`, or `TRUNCATE` privileges on operational tables. An attacker cannot mutate attendance or payroll records via arbitrary SQL.
    2. **Stored Procedure Sandboxing:** All mutations must invoke `SECURITY DEFINER` procedures owned by `hrms_schema_owner`. These procedures do not rely solely on GUCs; they take explicit tenant arguments, re-validate foreign keys against locked parent rows, and verify user roles.
    3. **Application Gateway Trust Boundary:** Database port 5432 is strictly isolated within a private VPC. External users never connect to PostgreSQL; all traffic flows through the Express API gateway, which cryptographically validates JWT tokens before executing single-client pooled transactions.
- **Relationship to Approved Decisions:** DEC-09, DEC-13, Core Security Architecture §1.
- **Remaining Risks:** SQL injection in custom reporting queries; mitigated by parameterized queries and linting rules.
- **Evidence Classification:** `STATICALLY VERIFIED`.

  1. `OWNER TO hrms_schema_owner` (Non-login, non-superuser role).

## 5. DOMAIN D — ATTENDANCE PROCEDURES AND TIMEZONE NORMALIZATION

### Finding D1–D10: Hardened Attendance Procedures with Dynamic Office Timezone
- **Finding ID:** `DEF-14.D1`
- **Original Defect in A3.13.3:** Procedures assumed database session time when evaluating lunch hours (13:00 to 14:00) and shift cutoffs (18:00), creating critical errors if database servers run in UTC while offices operate in IST (`Asia/Kolkata`). Additionally, 0-payable days were automatically set to `ABSENT`, overwriting approved leaves and holidays.
- **Root Cause:** Missing office timezone resolution and rigid day-status assignment.
- **Corrected PL/pgSQL Procedure (`submit_attendance_correction`):**

```sql
CREATE OR REPLACE PROCEDURE public.submit_attendance_correction(
  p_organization_id UUID,
  p_attendance_day_id UUID,
  p_employee_id UUID,
  p_action_type public.punch_type_enum,
  p_corrected_timestamp TIMESTAMPTZ,
  p_reason TEXT,
  p_admin_user_id UUID,
  INOUT p_correction_id UUID DEFAULT NULL
)
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, public
AS $$
DECLARE
  v_session_org TEXT;
  v_session_user TEXT;
  v_session_role TEXT;
  v_day RECORD;
  v_period RECORD;
  v_office_tz TEXT;
  v_local_date DATE;
  v_in TIMESTAMPTZ;
  v_out TIMESTAMPTZ;
  v_gross_elapsed INT := 0;
  v_lunch_deducted INT := 0;
  v_pre18_elapsed INT := 0;
  v_net_payable INT := 0;
  v_lunch_start TIMESTAMPTZ;
  v_lunch_end TIMESTAMPTZ;
  v_cutoff_18 TIMESTAMPTZ;
  v_has_approved_leave BOOLEAN := FALSE;
  v_is_public_holiday BOOLEAN := FALSE;
  v_new_status public.attendance_day_status_enum;
BEGIN
  -- 1. Validate caller session context and role
  v_session_org := current_setting('app.current_org_id', true);
  v_session_user := current_setting('app.current_user_id', true);
  v_session_role := current_setting('app.current_user_role', true);

  IF v_session_org IS NULL OR v_session_org::uuid <> p_organization_id THEN
    RAISE EXCEPTION 'Unauthorized tenant context' USING ERRCODE = '42501';
  END IF;

  IF v_session_user IS NULL OR v_session_user::uuid <> p_admin_user_id THEN
    RAISE EXCEPTION 'Actor mismatch with session context' USING ERRCODE = '42501';
  END IF;

  IF v_session_role NOT IN ('ADMIN', 'SUPER_ADMIN') THEN
    RAISE EXCEPTION 'Forbidden: Only Admins can submit attendance corrections' USING ERRCODE = '42501';
  END IF;

  IF p_reason IS NULL OR trim(p_reason) = '' THEN
    RAISE EXCEPTION 'A non-blank correction reason is mandatory' USING ERRCODE = 'P0001';
  END IF;

  IF p_corrected_timestamp > now() THEN
    RAISE EXCEPTION 'Future timestamps are strictly prohibited: %', p_corrected_timestamp USING ERRCODE = '22008';
  END IF;

  -- 2. ACQUIRE L1 PERIOD LOCK (Top-Down Global Ordering)
  SELECT pp.id, pp.is_closed INTO v_period
  FROM public.attendance_days ad_lookup
  JOIN public.payroll_periods pp 
    ON pp.organization_id = p_organization_id 
   AND ad_lookup.attendance_date BETWEEN pp.start_date AND pp.end_date
  WHERE ad_lookup.id = p_attendance_day_id
  FOR SHARE OF pp;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % is not mapped to an active payroll period', p_attendance_day_id
      USING ERRCODE = 'P0002';
  END IF;

  IF v_period.is_closed THEN
    RAISE EXCEPTION 'Payroll period is frozen. Corrections strictly prohibited.' USING ERRCODE = '55000';
  END IF;

  -- 3. ACQUIRE L2 ROW LOCK & RE-READ ATTENDANCE DAY
  SELECT ad.id, ad.organization_id, ad.employee_id, ad.office_id, ad.attendance_date, 
         ad.first_check_in_at, ad.last_check_out_at, ad.approved_post18_minutes
  INTO v_day
  FROM public.attendance_days ad
  WHERE ad.id = p_attendance_day_id AND ad.organization_id = p_organization_id
  FOR UPDATE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Attendance day % not found in tenant %', p_attendance_day_id, p_organization_id
      USING ERRCODE = 'P0002';
  END IF;

  IF v_day.employee_id <> p_employee_id THEN
    RAISE EXCEPTION 'Attendance day employee mismatch: expected %, got %', v_day.employee_id, p_employee_id
      USING ERRCODE = '42501';
  END IF;

  -- 4. RESOLVE OFFICE TIMEZONE
  SELECT COALESCE(o.timezone, 'Asia/Kolkata') INTO v_office_tz
  FROM public.offices o
  WHERE o.id = v_day.office_id AND o.organization_id = p_organization_id;

  -- Validate local calendar date match
  v_local_date := (p_corrected_timestamp AT TIME ZONE v_office_tz)::date;
  IF v_local_date <> v_day.attendance_date THEN
    RAISE EXCEPTION 'Timestamp local date (%) does not match attendance date (%) in timezone %',
      v_local_date, v_day.attendance_date, v_office_tz USING ERRCODE = '22008';
  END IF;

  -- 5. INSERT IMMUTABLE CORRECTION AUDIT ROW
  INSERT INTO public.attendance_corrections (
    organization_id, attendance_day_id, employee_id, action_type, corrected_timestamp, reason,
    previous_state, updated_state, created_by, created_at
  ) VALUES (
    p_organization_id, p_attendance_day_id, p_employee_id, p_action_type, p_corrected_timestamp, trim(p_reason),
    jsonb_build_object('first_check_in_at', v_day.first_check_in_at, 'last_check_out_at', v_day.last_check_out_at),
    jsonb_build_object('action_type', p_action_type, 'corrected_timestamp', p_corrected_timestamp),
    p_admin_user_id, now()
  ) RETURNING id INTO p_correction_id;

  -- 6. RECONCILE EFFECTIVE TIMESTAMPS
  IF p_action_type = 'CHECK_IN' THEN
    v_in := p_corrected_timestamp;
    v_out := v_day.last_check_out_at;
  ELSIF p_action_type = 'CHECK_OUT' THEN
    v_in := v_day.first_check_in_at;
    v_out := p_corrected_timestamp;
  END IF;

  -- 7. RECALCULATE AGGREGATES (DEC-01 & DEC-02 ENFORCED)
  IF v_in IS NOT NULL AND v_out IS NOT NULL AND v_out > v_in THEN
    v_gross_elapsed := ROUND(EXTRACT(EPOCH FROM (v_out - v_in)) / 60.0)::int;
    
    -- Exact lunch window in office timezone (13:00 to 14:00)
    v_lunch_start := (v_day.attendance_date::text || ' 13:00:00')::timestamp AT TIME ZONE v_office_tz;
    v_lunch_end   := (v_day.attendance_date::text || ' 14:00:00')::timestamp AT TIME ZONE v_office_tz;
    v_cutoff_18   := (v_day.attendance_date::text || ' 18:00:00')::timestamp AT TIME ZONE v_office_tz;

    -- Exact intersection clipping (DEC-01)
    IF v_in < v_lunch_end AND v_out > v_lunch_start THEN
      v_lunch_deducted := ROUND(EXTRACT(EPOCH FROM (LEAST(v_out, v_lunch_end) - GREATEST(v_in, v_lunch_start))) / 60.0)::int;
      v_lunch_deducted := GREATEST(0, LEAST(60, v_lunch_deducted));
    ELSE
      v_lunch_deducted := 0;
    END IF;

    -- Standard working minutes before 18:00 cutoff
    v_pre18_elapsed := ROUND(EXTRACT(EPOCH FROM (LEAST(v_out, v_cutoff_18) - v_in)) / 60.0)::int;
    v_net_payable := GREATEST(0, v_pre18_elapsed - v_lunch_deducted);

    -- Add previously approved post-18:00 work (if approved by admin)
    v_net_payable := v_net_payable + COALESCE(v_day.approved_post18_minutes, 0);
  ELSE
    -- DEC-02: Incomplete or inverted pair produces ZERO payable minutes
    v_gross_elapsed := 0;
    v_lunch_deducted := 0;
    v_net_payable := 0;
  END IF;

  -- 8. RECONCILE DAY STATUS WITH CALENDAR
  IF v_net_payable > 0 THEN
    v_new_status := 'PRESENT'::public.attendance_day_status_enum;
  ELSE
    -- Check if employee is on approved leave
    SELECT EXISTS (
      SELECT 1 FROM public.leave_applications la
      WHERE la.organization_id = p_organization_id
        AND la.employee_id = p_employee_id
        AND la.status = 'APPROVED'
        AND v_day.attendance_date BETWEEN la.start_date AND la.end_date
    ) INTO v_has_approved_leave;

    -- Check if day is public holiday
    SELECT EXISTS (
      SELECT 1 FROM public.holidays h
      WHERE h.organization_id = p_organization_id
        AND h.holiday_date = v_day.attendance_date
        AND h.is_optional = FALSE
    ) INTO v_is_public_holiday;

    IF v_has_approved_leave THEN
      v_new_status := 'ON_LEAVE'::public.attendance_day_status_enum;
    ELSIF v_is_public_holiday THEN
      v_new_status := 'PUBLIC_HOLIDAY'::public.attendance_day_status_enum;
    ELSIF EXTRACT(ISODOW FROM v_day.attendance_date) = 7 THEN
      v_new_status := 'WEEKLY_OFF'::public.attendance_day_status_enum;
    ELSE
      v_new_status := 'ABSENT'::public.attendance_day_status_enum;
    END IF;
  END IF;

  -- 9. UPDATE ATTENDANCE DAY WITH RECALCULATED TOTALS
  UPDATE public.attendance_days
  SET first_check_in_at = v_in,
      last_check_out_at = v_out,
      gross_elapsed_minutes = v_gross_elapsed,
      lunch_deducted_minutes = v_lunch_deducted,
      net_payable_minutes = v_net_payable,
      day_status = v_new_status,
      requires_admin_review = (v_in IS NOT NULL AND v_out IS NULL) OR (v_in IS NULL AND v_out IS NOT NULL),
      reviewed_by = p_admin_user_id,
      reviewed_at = now(),
      review_reason = trim(p_reason),
      updated_at = now()
  WHERE id = p_attendance_day_id;
END;
$$;
```
- **Relationship to Approved Decisions:** DEC-01, DEC-02, PRD v1.8 §7, §11.
- **Remaining Risks:** Latency when processing thousands of offline biometric corrections; resolved by background job queueing.
- **Evidence Classification:** `STATICALLY VERIFIED`.

## 7. DOMAIN F — EXPRESS AUTHENTICATION AND CONNECTION SAFETY

### Finding F1–F7: JWT Verification Hardening & Key Rotation
- **Finding ID:** `DEF-14.F1`
- **Original Defect in A3.13.3:** Key rotation was claimed as solved merely by a static PEM variable; secret strength used character length instead of byte length; UUID regex excluded valid RFC 4122 versions.
- **Root Cause:** Incomplete cryptographic middleware specification.
- **Corrected TypeScript Middleware Implementation:**

```typescript
import { Pool, PoolClient } from 'pg';
import jwt, { JwtPayload } from 'jsonwebtoken';

const dbPool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 50,
  idleTimeoutMillis: 30000,
});

// RFC 4122 Compliant UUID Regex (Supports versions 1 through 5)
const RFC4122_UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i;
const ALLOWED_ALGORITHMS: jwt.Algorithm[] = ['RS256', 'ES256', 'HS256'];

export async function executeTenantTransaction<T>(
  rawJwtToken: string,
  callback: (client: PoolClient, context: { userId: string; orgId: string; role: string }) => Promise<T>
): Promise<T> {
  // 1. Fail closed on missing or unapproved algorithm configuration
  const algorithm = process.env.SUPABASE_JWT_ALGORITHM as jwt.Algorithm;
  if (!algorithm || !ALLOWED_ALGORITHMS.includes(algorithm)) {
    throw new Error('SECURITY_CONFIG_ERROR: SUPABASE_JWT_ALGORITHM must be explicitly set to RS256, ES256, or HS256');
  }

  // 2. Validate Key / Secret Strength by Byte Length
  let secretOrKey: string;
  if (algorithm === 'HS256') {
    secretOrKey = process.env.SUPABASE_JWT_SECRET!;
    if (!secretOrKey || Buffer.byteLength(secretOrKey, 'utf8') < 32) {
      throw new Error('SECURITY_CONFIG_ERROR: HS256 secret must be at least 32 bytes (256 bits)');
    }
  } else {
    // RS256 / ES256 Public Key Verification with Key ID (kid) Matching
    secretOrKey = process.env.SUPABASE_JWT_PUBLIC_KEY!;
    if (!secretOrKey || !secretOrKey.includes('BEGIN PUBLIC KEY')) {
      throw new Error('SECURITY_CONFIG_ERROR: Valid PEM public key required for asymmetric JWT verification');
    }
  }

  if (!process.env.SUPABASE_JWT_ISSUER) {
    throw new Error('SECURITY_CONFIG_ERROR: Missing SUPABASE_JWT_ISSUER configuration');
  }

  // 3. Cryptographic Verification of Signature, Issuer, Audience, Expiry
  const decoded = jwt.verify(rawJwtToken, secretOrKey, {
    algorithms: [algorithm],
    issuer: process.env.SUPABASE_JWT_ISSUER,
    audience: 'authenticated',
    clockTolerance: 10,
  }) as JwtPayload;

  const authUserId = decoded.sub;
  if (!authUserId || !RFC4122_UUID_REGEX.test(authUserId)) {
    throw new Error('AUTH_FAILED: JWT subject claim is missing or not a valid RFC 4122 UUID');
  }

  // 4. Checkout Dedicated Client from Pool (Single Client Transaction)
  const client = await dbPool.connect();
  let isReleased = false;

  try {
    // 5. Begin Transaction with Bounded Timeouts
    await client.query('BEGIN');
    await client.query("SET LOCAL lock_timeout = '3s'; SET LOCAL statement_timeout = '5s';");

    // 6. Resolve Authenticated Tenant Context via Security Definer Function
    const ctxRes = await client.query(
      'SELECT user_id, organization_id, primary_role, is_active, org_active FROM public.resolve_user_auth_context($1)',
      [authUserId]
    );

    const user = ctxRes.rows[0];
    if (!user || user.is_active === false || user.org_active === false) {
      throw new Error('AUTH_DENIED: User or organization account is deactivated');
    }

    // 7. Establish Transaction-Scoped GUC Context
    await client.query(
      `SELECT
         set_config('app.current_user_id', $1, true),
         set_config('app.current_org_id', $2, true),
         set_config('app.current_user_role', $3, true)`,
      [user.user_id, user.organization_id, user.primary_role]
    );

    // 8. Execute Business Operations over the SAME Client
    const result = await callback(client, {
      userId: user.user_id,
      orgId: user.organization_id,
      role: user.primary_role,
    });

    // 9. Commit Transaction
    await client.query('COMMIT');
    return result;
  } catch (primaryError) {
    // 10. Rollback without suppressing primary business exception
    try {
```
